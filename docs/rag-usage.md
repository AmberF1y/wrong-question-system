# 个人错题库 RAG 学习助手（F-013）

更新日期：2026-10-13。入口为左侧「错题库学习助手」或错题详情的「询问学习助手」。

## 使用方式

1. 在错题中保存题干、自己的错误答案、正确答案、解析、错误原因和知识点。
2. 打开助手，选择全部科目或一个科目，可进一步选择复习中 / 已掌握。
3. 输入具体问题，例如「我的二分查找错题中，边界条件容易错在哪里？」。
4. 查看回答与 S1、S2 等来源，展开原文，点击查看完整错题。来源是在当时检索到的片段，题目后来修改或删除会显示提示。
5. 如要联系上一问题，主动勾选「联系上一问题进行追问」。只使用同科目、同掌握范围中上一条成功请求的问题作为检索上下文，不把历史模型回答当成新证据。

资料不足会明确说明。系统不联网寻找题目，不自动解题、创建或修改错题，也不代替复习评价。助手只能使用保存的文本；图片须先通过 AI 辅助录入并由人核对保存。

## 无密钥也能使用

默认 `AI_MODE=disabled`：使用本地中文双字词 / 英文关键词 BM25 检索，显示真实错题原文。结果类型为 `RETRIEVAL_ONLY`，不伪装成 AI 回答，不消耗模型额度。

`AI_MODE=demo` 的助手也只展示真实检索结果，明确标注未调用回答模型；与图片识别的演示草稿不同，助手没有模拟生成内容。

## 接入真实回答与语义检索

复用 [AI 服务配置](ai-usage.md) 的 `AI_MODE=compatible`、`AI_BASE_URL`、`AI_API_KEY`。地址以兼容服务的 API 根路径结束，例如带 `/v1`，后端追加 `/chat/completions` 和 `/embeddings`。远程地址必须 HTTPS，只有 localhost / 127.0.0.1 / IPv6 loopback 可使用 HTTP。密钥仅由后端环境读取，不传前端或存数据库。

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| RAG_MODEL | AI_MODEL | 兼容聊天模型；应能可靠输出带引用的 JSON |
| RAG_EMBEDDING_ENABLED | false | 是否调用真实向量接口 |
| RAG_EMBEDDING_MODEL | 空 | 启用向量时必须配置支持 `/embeddings` 的模型名称 |
| RAG_TOP_K | 6 | 最多 1～8 个来源片段；每题最多两个 |
| RAG_MINIMUM_SIMILARITY | 0.45 | 语义候选最低余弦相似度，需针对实际模型调优 |
| RAG_CONCURRENCY | 1 | 学习助手工作线程 1～4；适用于一个后端实例 |
| RAG_MAX_QUESTIONS | 5000 | 单次检索范围题目上限，可配置 100～10000 |
| RAG_MAX_CHUNKS | 10000 | 全库索引片段上限，可配置 100～20000 |
| RAG_EMBEDDING_BATCHES | 3 | 一轮最多 1～5 批，每批最多 16 个片段 |
| RAG_INPUT_PRICE_PER_MILLION | 未配置 | 回答模型每百万输入 token 的单价 |
| RAG_OUTPUT_PRICE_PER_MILLION | 未配置 | 回答模型每百万输出 token 的单价 |
| RAG_EMBEDDING_PRICE_PER_MILLION | 未配置 | 向量模型每百万输入 token 的单价 |

单价币种由服务端配置约定，所有单价应使用同一币种；估算不等于账单。未报告用量或未配置单价的成本保持未知，不按零处理。输出兼容性可用既有 `AI_RESPONSE_FORMAT=json_object` 或 `none`；即使服务不支持 response_format，结果仍须满足严格 JSON 与引用校验。

启用向量时，提问或「更新索引」会为变化片段生成真实向量。默认一轮最多索引 48 个片段，问答另外可能发送一次问题向量请求、一次回答请求。首次题库较大时，可分多次更新；页面会说明未完成的向量覆盖。向量失败时保留关键词检索，回答模型失败会保留来源并标记失败。

每一次向量 / 回答请求都与图片识别共享 `AI_DAILY_CALL_LIMIT`，按业务时区预占一次额度。索引命中缓存、本地检索不占额度。取消和删除记录不返还已发送请求的额度。密钥缺失、地址无效或演示模式不会发送真实模型请求。

注意：启用兼容模式后，选中的错题片段、知识点以及当前问题将发给配置的服务；建立向量索引会发送当前范围内待索引的错题文本。模型配置不通过网页编辑。

## 恢复与删除

- 上传问题使用 UUID 幂等编号。同编号、同问题与范围只创建一次；不同内容会返回冲突。
- 请求响应不确定时，页面保存请求编号，只查询服务器，不自动重发。刷新后仍可同步。
- 超时、返回格式错误、后端重启或处理停滞会保留错误与调用记录；只允许人工有限重试。重试携带已观察到的轮次，过期重复操作不会再创建一轮。
- 取消不保证撤回已经发送给模型的请求；迟到回答被丢弃，实际已报告用量仍记录。
- 同一对话只能有一个正在处理的问题；删除对话须等其请求与已发送调用结束。删除对话会级联删除问答与调用记录，保留错题、索引和每日额度。
- 原题删除会自动删除其索引片段；历史回答保留当时的来源原文，并标记原题已删除。修改题目、科目或知识点名称会令内容哈希变化，下一次提问刷新该题索引；回答生成期间检测到来源变化会拒绝发布该回答。

默认保存的对话包含个人问题与错题来源快照，全库备份会包含这些内容。沿用本地单用户边界，不应把无登录服务直接暴露到公网。正式库启动前按 [本地备份说明](local-usage.md) 备份；本分支新增 V5，Flyway 顺序补齐待执行迁移，不修改旧迁移。

## 验证与展示

已验证真实 MySQL 上的索引增量更新、删除清理、科目 / 掌握范围、引用校验、额度、取消、重启恢复、人工重试、会话幂等与问题追问。兼容模型测试使用本地 HTTP 协议夹具，验证真实的 HTTP 请求、向量解析、混合检索、引用和用量记录；夹具的数值不代表真实语义效果。

本轮未配置真实模型密钥，因此未宣称真实模型的回答准确率、语义召回率或价格已验证。配置后应挑选至少 20 个真实问题，记录正确来源、无资料问题、回答事实与引用一致性，针对模型调整相似度阈值，再用于求职演示。索引使用内存精确扫描，适合有上限的本地题库；本轮没有做容量或并发性能承诺。
