# ADR-004：AI 图片任务的持久化、模型边界与恢复

- 日期：2026-10-11
- 状态：已采纳，适用于 F-011 / F-012 单用户本地实例

## 背景

题图识别耗时且可能计费，浏览器断网或后端重启不能被视为「请求肯定没执行」。模型还可能返回错误 JSON、过长内容、猜出的答案和不存在的知识点。需要降低录入成本，同时保留用户核对、现有错题校验和复习规则。

## 决定

1. 新增 Flyway V4 的 `ai_task`、`ai_call_record`、`ai_daily_usage`。使用 MySQL 持久化队列，固定线程池和信号量限制并发，不为当前单实例规模引入消息中间件。JDBC 明确使用 `FOR UPDATE SKIP LOCKED` 领取任务；调用模型前提交短事务。
2. 模型接入独立在 `AiVisionClient`，使用 Java 21 HttpClient 与已有 Jackson 3。当前只需单种兼容图片聊天协议，不增加 SDK、编排框架或全局客户端状态。以后需要其他协议可替换该适配层。
3. 默认关闭模型；显式 demo 无外部请求且全程标注模拟。密钥只在后端环境，远程 HTTPS、禁止重定向，响应体最多 1 MiB，整次异步请求含响应体有截止时间，错误只保存归一化代码与安全信息。
4. 提示词只要求转录图中已有内容，输出严格字段。服务端检查字段类型与长度，推荐 ID 必须属于提交快照和当前同科目知识树。个人错误答案和错误原因不来自模型。任何草稿必须人工确认入库。
5. 上传用客户端 UUID 加图片 SHA-256 和科目范围保证幂等。重试用已观察的 retryCount 防止过期请求再启动一轮。确认通过任务行锁，在与既有 JPA 错题服务共享的事务中创建题目、复制图片、标记 APPLIED；文件操作复用现有补偿机制。
6. 每次执行先原子预占业务日期额度；失败、重试、超时和演示也计数，取消/删除不返还。每日额度行直接取排他锁，避免 INSERT IGNORE 的共享锁升级导致并发死锁。仅有已报告用量和两个配置单价时估算成本。
7. 瞬时错误有限重试。重启或看门狗恢复不会重发可能已计费的 RUNNING；标记失败/中断供用户判断。取消不能保证服务商停止计费，迟到结果依据任务状态和尝试序号丢弃。
8. 图片输入在已有存储根的 `ai-tasks` 子目录，确认后的题图独立复制，适配现有整目录备份。浏览器只缓存人工编辑和不确定操作标记，服务端保留初始草稿，不自动覆盖本地人工编辑。

## 结果与边界

请求等待、实际识别、草稿核对和错题保存相互独立，浏览器可以离开后继续。自动化测试能用本地 HTTP 模型夹具验证协议和异常，无需真实密钥或外部费用。识别质量需真实模型样本集另行评测。

单实例恢复会处理库中所有 RUNNING，因此不允许多个后端共享此队列。调用次数控制不等同于金额预算。JSON 和知识点校验不能证明模型转录准确，也不能完全消除提示注入。数据库和文件系统之间仍可能有崩溃残留文件；无定期保留策略，维护时按引用检查清理。

没有对既有评价响应恢复、F-010 抽查或滚动复习策略做修改；新增错题复用原规则安排首次复习。
