# ADR-003：题目图片使用本地文件系统与相对存储键

## 状态

Accepted；已在 F-008 实现并通过自动化、真实浏览器和合并后回归验证，
通过 Pull Request #8 合并到 `main`。

日期：2026-09-05

## 背景

F-001～F-007 已经支持错题文字录入、知识点关联和每日复习，但真实题目经常
包含公式、图表或无法完整转写的排版。F-008 需要在单用户本地部署场景中增加
一张可选原题图片，同时保持现有文字字段必填，并为后续 OCR 留出空间。

V1 已经在 `question` 表中预留可空的 `image_path VARCHAR(500)`，详情和到期题
响应也已有 `imagePath`。当前没有多图、云部署、跨用户隔离或 CDN 需求。

数据库事务和本地文件系统操作不能组成一个真正的原子事务，因此上传、替换、
移除和随题删除还需要明确失败与清理策略。

## 决策

### 1. 图片二进制保存在可配置的本地文件系统

默认根目录：

```text
./data/question-images
```

配置项和环境变量：

```text
app.storage.question-image-directory
APP_QUESTION_IMAGE_DIRECTORY
```

该目录属于运行时数据，不进入 Git，也不放在前端静态资源目录中。

### 2. MySQL 只保存服务端生成的相对存储键

复用已有 `question.image_path`，不新增表或 Flyway 迁移。路径格式为：

```text
questions/{questionId}/{uuid}.{extension}
```

数据库不保存图片二进制、绝对路径或客户端原文件名。题目 ID 来自数据库，
文件名由 UUID 生成，扩展名来自服务端识别的实际内容格式。

### 3. 当前模型是一题最多一图

`image_path IS NULL` 表示无图，非空表示一张题图。上传到已有图片的错题即为
替换。只有出现真实多图需求时才引入 `question_image` 表，不在字符串字段中
拼接多个路径。

### 4. 服务端验证内容，不信任客户端声明

- 支持 PNG、JPEG、WebP、GIF；
- 单文件最大 20 MiB；
- 根据文件签名识别格式；
- 不信任原文件名、扩展名或客户端 MIME；
- 拒绝 SVG、空文件、损坏内容和无法识别的格式；
- 路径解析必须保持在配置根目录内，并拒绝绝对路径、目录逃逸和符号链接。

### 5. 图片只通过受控 API 读取

使用 `GET /api/questions/{questionId}/image` 返回原始字节，不把存储目录作为
静态目录公开。响应使用实际图片 MIME，并设置：

```http
Content-Disposition: inline
X-Content-Type-Options: nosniff
Cache-Control: no-store
```

错题不存在与错题无图/文件缺失保持不同的 404 错误语义。图片读取失败只影响
图片区域，不影响题目文字。

### 6. 使用事务回调管理文件生命周期

上传或替换时先写临时文件，在同一文件系统内移动到最终路径，再更新数据库。
数据库回滚时删除新文件；数据库提交后删除被替换、移除或随错题删除的旧文件。

这不能提供跨 MySQL 与文件系统的绝对原子性，但能避免数据库提交一个上传失败
的路径，并把旧文件清理延迟到数据库状态确定之后。

### 7. 文字与图片使用独立请求

创建带图错题时先通过 JSON 创建错题并取得 ID，再上传图片。如果图片失败，
错题仍已创建，客户端不得重发创建请求，而应进入编辑页只重试图片。

修改文字不会触碰原图；替换和移除图片使用独立接口。客户端必须准确提示部分
成功，不能把已提交成功的操作描述为整体失败。

## 影响

正面影响：

- 复用既有字段，不需要数据库迁移；
- 本地单用户部署简单，不引入外部服务；
- 数据库备份不混入大体积二进制；
- 相对存储键允许以后更换根目录；
- 服务端内容校验和受控读取减少路径与同源脚本风险；
- 图片失败不会阻断文字录入与复习。

代价与风险：

- 数据库备份不会自动包含图片目录，备份和迁移必须同时处理两者；
- 文件系统与数据库无法绝对原子提交，进程在特定时刻崩溃仍可能产生孤儿文件；
- 多实例部署需要共享存储或改用对象存储；
- `no-store` 会增加重复读取流量，但避免替换后展示旧缓存，适合当前本地规模；
- 一题一图不能表达多页题目，后续需求成立时需要新表和新 API。

## 未选择的方案

### 图片存入 MySQL BLOB

会增大数据库、备份和查询压力，并把文件传输与业务行存储耦合。当前没有必须
依赖数据库原子保存二进制的需求，拒绝。

### 对象存储或 CDN

适合云端、多实例和大规模访问，但当前是单用户本地部署，引入凭据、SDK、网络
失败和额外运维没有收益，暂不采用。

### 直接公开上传目录

难以按错题存在性控制读取，也更容易暴露任意文件路径和错误 MIME。采用受控
API 读取。

### 在 F-008 同时加入 OCR

OCR 需要识别任务、文本校对和失败恢复等独立产品设计。F-008 只建立“图片 +
手工文字”的可靠闭环，OCR 留给后续 Feature。
