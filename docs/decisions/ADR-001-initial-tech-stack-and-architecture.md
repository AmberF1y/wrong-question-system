# ADR-001：第一版技术栈与项目架构

* **状态：** 已接受（Accepted）
* **日期：** 2026-08-21
* **最后修正：** 2026-08-23

## 1. 背景

本项目是一个个人使用的：

> **错题整理 + 滚动复习系统**

主要目标是解决两个问题：

1. 把学习过程中产生的错题方便地保存下来。
2. 根据复习规则，在合适的时间重新安排这些错题进行复习。

第一版主要由我自己使用，以电脑浏览器为主要使用环境。

项目首先要做到真正可用，其次才考虑工程复杂度和求职展示价值。

因此，第一版不为了“看起来高级”而主动加入没有实际需求的复杂技术。

---

## 2. 第一版采用的技术

### 后端

采用：

* Java 21
* Spring Boot
* Maven

简单理解：

* **Java 21**：后端主要使用的编程语言。
* **Spring Boot**：帮助我们开发 Java Web 后端。
* **Maven**：管理 Java 项目的依赖、编译、测试和打包。

### 数据库

采用：

* MySQL
* Spring Data JPA

简单理解：

* **MySQL**：保存错题、知识点、复习相关数据。
* **Spring Data JPA**：负责 Java 对象与数据库表之间的映射，并帮助后端完成常见的数据库操作。

当前阶段不引入 MyBatis、MyBatis-Plus。

数据库结构变更管理工具暂未正式确定，后续在实际出现数据库版本迁移需求时再单独决策。

### 前端

采用：

* Vue 3
* TypeScript
* Vite
* Element Plus

简单理解：

* **Vue 3**：负责开发浏览器中看到的页面。
* **TypeScript**：前端主要使用的编程语言。
* **Vite**：帮助创建、运行和打包 Vue 项目。
* **Element Plus**：提供按钮、表格、输入框等现成的页面组件。

---

## 3. 系统整体结构

第一版采用前后端分离。

大致结构如下：

```text
浏览器
  ↓
Vue 前端
  ↓
HTTP / REST API / JSON
  ↓
Spring Boot 后端
  ↓
Spring Data JPA
  ↓
MySQL
```

例如以后用户保存一道错题，大致流程会是：

```text
在网页填写错题
↓
Vue 收集填写的数据
↓
发送给 Spring Boot
↓
Spring Boot 处理业务
↓
通过 Spring Data JPA 操作 MySQL
↓
数据保存完成
```

---

## 4. 后端如何组织

第一版只运行：

> **一个 Spring Boot 后端程序**

暂时不使用微服务。

但是，为了避免以后所有代码混在一起，后端会按照不同业务进行划分。

目前计划包括：

```text
question
```

负责错题相关功能。

```text
knowledge
```

负责知识点和知识树。

```text
review
```

负责每日复习和滚动复习。

```text
dashboard
```

负责首页统计。

```text
media
```

负责题目图片。

```text
ocr
```

为未来 OCR 功能保留位置。

也就是说：

> 程序仍然只有一个，但是内部按照不同业务整理代码。

这种方式称为：

> **模块化单体（Modular Monolith）**

---

## 5. 图片如何保存

第一版采用：

> 图片文件保存在本地文件夹中，MySQL 保存图片相关信息和文件位置。

暂时不把图片文件本身直接保存进 MySQL。

当前 MVP 阶段，错题表可以直接保存题目图片路径。

如果以后出现一道题对应多张图片等真实需求，再考虑拆分独立的图片数据表。

未来如果本地文件存储无法满足需求，可以再考虑对象存储等其他方案。

---

## 6. OCR 怎么处理

OCR 是项目未来的重要功能。

理想流程是：

```text
上传题目图片
↓
OCR 自动识别题目
↓
用户修改少量错误
↓
保存错题
```

但是：

> OCR 不能阻塞第一版开发。

如果第一版 OCR 实现起来成本较高，可以先采用：

```text
上传题目图片
↓
手动填写题目文字
```

以后再增加 OCR。

在设计代码时，会尽量给 OCR 留出独立的位置，避免以后增加 OCR 时需要大改整个系统。

## 7. 为什么选择这套方案

### 能满足现在的需求

当前系统主要需要：

* 管理错题
* 管理知识点
* 保存复习相关数据
* 安排每日复习
* 做简单的数据统计
* 保存题目图片

目前这套技术已经足够完成这些功能。

### 技术成熟

Java、Spring Boot、Spring Data JPA、MySQL、Vue 等都有成熟的开发生态和大量学习资料。

### 与当前项目实现保持一致

F-001 已经实际引入并使用：

* Spring Data JPA
* MySQL Connector

因此第一版继续使用 Spring Data JPA，避免在没有真实需求的情况下更换数据访问技术。

### 适合项目逐步发展

项目未来还可能增加：

* OCR
* 更复杂的复习算法
* 薄弱知识点分析
* 同知识点专项训练
* 更多统计功能

当前方案能够支持这些功能逐步增加。

### 暂时没有必要使用更复杂的技术

目前暂时不使用：

* MyBatis
* MyBatis-Plus
* Redis
* RabbitMQ
* Kafka
* Spring Cloud
* 微服务
* Elasticsearch
* Kubernetes
* 分布式锁

原因不是这些技术不好，而是：

> **当前项目还没有出现必须使用它们的问题。**

如果以后真的出现对应需求，再考虑加入。

---

## 8. 以后什么时候需要重新考虑

如果未来出现以下情况，可以重新评估当前技术方案：

* 系统不再只是单用户使用。
* 数据量明显变大。
* Spring Data JPA 已经明显不适合某些复杂数据库操作。
* OCR 处理大量图片并且速度成为问题。
* 本地保存图片已经无法满足需求。
* 某个模块需要独立运行。
* 当前技术方案已经明显影响开发或使用体验。

如果以后做出了新的重要技术决定，应新增新的 ADR，而不是直接删除过去的决策记录。

---

## 9. 当前结论

第一版正式采用：

```text
后端：
Java 21
Spring Boot
Maven
Spring Data JPA

数据库：
MySQL

前端：
Vue 3
TypeScript
Vite
Element Plus

架构：
前后端分离
模块化单体

图片：
本地文件存储
数据库保存图片路径

OCR：
预留位置，第一版允许暂不实现
```

当前阶段不主动引入复杂分布式技术。

项目后续按照：

> **真实需求 → 出现问题 → 再选择合适技术解决**

的方式逐步演进。
