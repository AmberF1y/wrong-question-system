## 5. Feature 目标

F-007 的核心目标是在现有后端规则之上建立可真实使用的每日复习前端闭环：

```text
进入每日复习
→ 选择全部科目或单个科目
→ 获取当前下一道到期题
→ 只显示题目
→ 用户在纸上重新作答
→ 主动点击查看答案
→ 获取并显示完整答案与解析
→ 选择四级评价
→ 后端更新状态并写入历史
→ 前端展示服务器返回的结果
→ 用户点击下一题
→ 重新查询动态队列
→ 全部完成时显示空队列
```

F-007 同时为已掌握错题详情提供“重新加入复习”操作，使 F-005 已实现的
重新加入能力可以通过浏览器使用。

前端只负责交互和展示，不复制后端调度规则，不计算下一次复习日期，也不保存
用户在纸上的本次答案。

## 7. 已确认产品与交互决策

### 7.1 页面范围

1. 每日复习默认查询全部科目。
2. 页面允许切换为单个科目。
3. 科目选项来自现有知识点 Store 的根节点。
4. 已掌握错题重新加入复习纳入 F-007。
5. 重新加入入口只出现在已掌握错题详情页，不放在每日复习页面。

### 7.2 正常复习交互

1. 初始阶段只显示待复习 DTO 中允许提前显示的内容。
2. 点击“查看答案”后才请求 `GET /api/questions/{id}`。
3. 详情成功加载后才显示和启用四级评价。
4. 评价按钮同时显示中文等级和固定规则效果。
5. 评价成功后先展示结果。
6. 用户点击“下一题”后才重新获取动态队列。
7. 不自动跳过评价结果。
8. 科目切换立即生效并重新查询。
9. 尚未评价的题仍保留在原科目队列中，不产生服务端状态变化。
10. 评价 POST 提交期间禁用科目切换。

### 7.3 异常恢复

1. 评价请求断线或超时后不自动重发 POST。
2. 页面显示“评价结果暂时无法确认”。
3. 用户通过“同步复习进度”发起安全 GET 查询。
4. 明确收到 404 或复习 409 时，显示原因后自动重新查询队列。
5. 查看答案失败时保留当前题，继续隐藏答案，并允许重新加载答案。
6. 答案详情成功前不得评价。

### 7.4 重新加入复习

1. 操作前显示确认框。
2. 确认内容说明题目将立即进入今日队列并记录重新加入事件。
3. 成功后停留在详情页。
4. 使用服务器结果并重新加载详情。
5. 成功后提供“前往每日复习”入口。
6. 404 显示资源不存在。
7. 409 显示后端原因并重新加载详情。

### 7.5 真实验收数据

1. 临时知识点和错题先通过真实页面或现有 API 创建。
2. 所有临时 ID 必须记录。
3. 只对明确临时题 ID 调整 `next_review_date`。
4. 第一次熟练通过真实前端和后端完成。
5. 为当天完成第二次熟练，只把该临时题的下一日期调整回当天。
6. 第二次熟练和重新加入继续通过真实页面完成。
7. 清理优先通过现有删除 API。
8. 最后通过只读 SQL 按精确 ID 核对五张表。
9. API 清理失败时停止并报告，不擅自扩大 SQL 删除范围。

## 8. 后端 API 契约

F-007 只复用已有契约。

### 8.1 获取下一道待复习题

```http
GET /api/reviews/due/next
GET /api/reviews/due/next?subject=408
```

有题响应：

```json
{
  "dueCount": 3,
  "question": {
    "id": 42,
    "questionText": "题目内容",
    "imagePath": null,
    "subject": "408",
    "nextReviewDate": "2026-09-01"
  }
}
```

空队列：

```json
{
  "dueCount": 0,
  "question": null
}
```

前端不得从该响应读取或假设答案、解析、错误原因或知识点。

### 8.2 查看完整答案

```http
GET /api/questions/{id}
```

复用现有 `QuestionDetail`。不得在初始页面加载时预取该接口。

### 8.3 提交评价

```http
POST /api/reviews/{questionId}/evaluations
Content-Type: application/json
```

```json
{
  "rating": "BASICALLY_MASTERED"
}
```

成功响应：

```json
{
  "questionId": 42,
  "eventType": "EVALUATION",
  "rating": "BASICALLY_MASTERED",
  "occurredAt": "2026-09-03T10:20:30Z",
  "reviewStatus": "ACTIVE",
  "nextReviewDate": "2026-09-10",
  "consecutiveProficientCount": 0,
  "lastReviewedAt": "2026-09-03T10:20:30Z"
}
```

响应不包含下一题和新的 `dueCount`。前端不得在本地把原数量减一后当作服务器
事实；点击下一题时重新查询。

### 8.4 重新加入

```http
POST /api/reviews/{questionId}/reactivate
```

请求无 body。成功响应使用同一操作结果结构，`eventType` 为
`REACTIVATION`，`rating` 为 `null`。

### 8.5 复习错误码

| HTTP | code | F-007 处理 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 保留答案阶段，显示后端消息或字段错误 |
| 400 | `MALFORMED_REQUEST_BODY` | 保留答案阶段，显示后端消息；正常类型安全 UI 不应生成 |
| 404 | `QUESTION_NOT_FOUND` | 显示原因并重新同步队列或详情 |
| 409 | `REVIEW_NOT_DUE` | 显示原因并重新查询队列 |
| 409 | `REVIEW_ALREADY_MASTERED` | 显示原因并重新查询队列 |
| 409 | `REVIEW_NOT_MASTERED` | 重新加载错题详情 |
| 409 | `REVIEW_CONCURRENT_MODIFICATION` | 显示原因并重新查询服务器状态 |

## 12. 页面状态模型

每日复习页面使用明确的局部阶段，不把全部状态压缩成多个可能互相矛盾的
布尔值。建议至少区分：

```text
LOADING_QUEUE
QUEUE_ERROR
EMPTY
QUESTION
LOADING_ANSWER
ANSWER_ERROR
ANSWER
SUBMITTING
RESULT
UNCERTAIN
```

状态含义：

- `LOADING_QUEUE`：首次加载、切换科目或点击下一题；
- `QUEUE_ERROR`：下一题请求失败，可重试；
- `EMPTY`：服务器明确返回 `dueCount=0`、`question=null`；
- `QUESTION`：只展示待复习题；
- `LOADING_ANSWER`：正在请求错题详情；
- `ANSWER_ERROR`：详情失败但当前题保留；
- `ANSWER`：详情已加载，可以评价；
- `SUBMITTING`：评价 POST 正在执行；
- `RESULT`：服务器明确返回评价结果，或安全同步发现状态已经更新；
- `UNCERTAIN`：POST 无响应，不能确定服务器是否提交。

复习状态是页面局部、短生命周期状态，不写入 Pinia。离开页面后重新进入时，
直接从后端动态队列重新开始。这样可以避免浏览器缓存题单与数据库状态漂移。

- 页面数量文案说明 `dueCount` 包含当前题；
- 空状态区分“全部待复习已完成”和“当前科目待复习已完成”。

### 13.2 知识树加载失败

科目选项依赖知识点 Store，但每日复习的全部科目队列不依赖知识树。

因此页面挂载时：

- 队列请求和知识树加载相互独立；
- 知识树失败只显示筛选不可用警告；
- 不阻止全部科目队列；
- 允许用户重试知识树加载。

### 13.3 切换行为

- 非提交阶段允许立即切换；
- 切换后清理当前详情、评价结果和局部错误；
- 立即请求新筛选条件下的动态队列；
- 未评价题没有服务端变化，仍保留在原队列；
- `SUBMITTING` 阶段禁用筛选；
- 不增加二次确认。

### 13.4 请求竞态

快速连续切换科目时，较早请求可能晚于新请求返回。

页面使用递增请求序号或等价的失效标记，只允许最新请求更新页面。旧队列或
旧详情响应不得覆盖当前科目和当前题。该机制必须有自动化测试。

## 18. 空队列

只有服务器明确返回以下组合时进入空状态：

```text
dueCount = 0

```

空状态：

- 全部科目：“今天没有待复习错题”；
- 单科目：“当前科目今天没有待复习错题”；
- 提供刷新操作；
- 单科目可以清除筛选查看全部科目；
- 不把请求失败显示为空队列；

响应并提示重新加载，不自行修复数字。

## 19. 评价请求不确定状态

### 19.1 问题

Axios 超时或连接中断可能发生在：

```text
后端事务已经提交
→ 成功响应在网络中丢失
→ 前端收到无响应错误
```

因此“前端没有收到成功响应”不等于“后端没有评价成功”。

### 19.2 处理原则

- 不自动重发 POST；
- 不显示“评价失败，请重试”这种确定性结论；
- 进入 `UNCERTAIN`；
- 保留题目、答案和提交前复习摘要；
- 暂时禁用再次评价；
- 显示“评价结果暂时无法确认”；
- 提供“同步复习进度”。

### 19.3 安全同步

查看答案时已经获得提交前的 `QuestionDetail` 复习摘要。同步时重新请求同一道题
详情，并与提交前摘要比较：

- 状态、下次日期、连续熟练次数或最后复习时间发生变化：服务器状态已经推进，
  展示“服务器状态已更新”的同步结果，不虚构具体事件一定来自当前标签页；
- 摘要没有变化：返回答案阶段，允许用户重新提交；
- 题目 404：显示题目不存在并重新加载队列；
- 同步 GET 失败：继续保持不确定状态，允许再次同步。

如果原评价事务在同步后才完成，后续再次提交会由后端返回 409，页面再按 409
规则同步，因此不会造成同一到期周期被推进两次。

## 20. 409 与多标签页

当前后端动态队列允许两个浏览器标签页同时看到同一道题。首个评价成功后，
另一个标签页可能收到：

- `REVIEW_NOT_DUE`；
- `REVIEW_ALREADY_MASTERED`；
- `REVIEW_CONCURRENT_MODIFICATION`。

页面必须：

1. 展示后端具体消息；
2. 不把冲突伪装成成功；
3. 不本地覆盖服务器状态；
4. 自动重新获取当前筛选条件下的队列；
5. 如果重新获取失败，显示队列错误并提供重试。

客户端按钮禁用只防止同一页面快速连点，后端乐观锁和业务校验仍是并发正确性
的最终保证。

- 不同科目均准备到期题，验证筛选。

SQL 必须：

- 执行前查询目标行；
- 使用显式事务；
- WHERE 使用明确 `question_id IN (...)`；
- 更新后查询确认；
- 不修改非临时题；
- 不增加生产测试接口。

### 28.3 连续熟练

1. 将目标临时题设为到期；
2. 在真实页面查看答案；
3. 第一次提交 `PROFICIENT`；
4. 核对结果为 ACTIVE、连续熟练 1、日期加 14 天；
5. 只把该临时题当前下一日期调整为当天；
6. 再次进入每日复习；
7. 第二次提交 `PROFICIENT`；
8. 核对 MASTERED、连续熟练 2、下一日期为空；
9. 从错题详情执行重新加入；
10. 核对 ACTIVE、连续熟练 0、当天到期；
11. 核对重新出现在每日复习队列。

日期调整是验收夹具的人为时间推进，可能使第一条历史的结果日期与随后人工
提前的当前状态之间出现测试期内的时间跳跃。该数据不作为真实学习历史保留，
验收后整题和历史一并删除。

## 33. 风险与处理

### 33.1 提前泄露答案

风险：页面挂载时预取详情，即使模板隐藏，答案仍进入浏览器内存和网络记录。

处理：点击查看答案后才调用详情接口，并通过 Mock API 测试调用时机。

### 33.2 把动态数量当固定进度

风险：并发操作、跨科目切换和新到期题会改变 dueCount。

处理：只显示服务器当前数量和“包含本题”，不显示固定总进度。

### 33.3 POST 响应丢失

风险：后端已经提交，但前端认为失败并重复提交。

处理：进入不确定状态，不自动重发，使用 GET 同步摘要；后端冲突继续兜底。

### 33.4 多标签页状态过期

风险：两个标签页评价同一道题。

处理：按钮锁只处理单页，409 后重新查询；后端 `@Version` 是最终保证。

### 33.5 筛选响应乱序

风险：旧 subject 请求晚返回并覆盖新 subject。

处理：请求序号使旧响应失效，并加入自动化测试。

### 33.6 知识树失败阻塞复习

风险：科目选项请求失败导致全部队列也无法使用。

处理：两项请求独立；筛选失败不阻止全部科目。

### 33.7 图片路径不可访问

风险：错误地把 imagePath 当 URL 渲染。

处理：F-007 不展示图片，图片能力留给独立 Feature。

### 33.8 浏览器与业务时区不同

风险：精确 Instant 按浏览器时区显示，与后端业务日期不一致。

处理：调度结果主要展示 LocalDate；不把格式化时刻解释为业务日期。

### 33.9 验收直接 SQL

风险：误改真实数据或制造无法清理的临时数据。

处理：只用精确临时 ID、事务、前后查询、执行前确认、API 清理和最终只读核对。

### 33.10 范围膨胀

风险：每日复习继续扩展到 Dashboard、历史、抽查或算法。

处理：严格遵守第 6 节，不在 F-007 临时增加。
