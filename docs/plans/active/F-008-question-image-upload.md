## 2. 目标

在现有错题文字录入与每日复习闭环上增加真实题目图片能力：

```text
选择图片
→ 本地预览
→ 保存错题
→ 后端校验并写入受控目录
→ 数据库保存相对路径
→ 详情与每日复习按需读取图片
→ 支持替换、移除和随错题删除清理
```

F-008 完成后，用户可以使用“图片 + 手工文字”录入真实错题。OCR 继续留给
后续 Feature，不在 F-008 中实现。

---

## 3. 已确认产品规则

- 每道错题最多一张题目图片；
- 图片可选，没有图片时仍允许创建和修改错题；
- 图片保存在本地文件系统，MySQL 只保存生成后的相对路径；
- 支持 PNG、JPEG、WebP 和 GIF；
- 单文件最大 20 MiB；
- 不接受 SVG、BMP、TIFF、HEIC 或任意其他文件格式；
- 创建页、编辑页提供选择与预览；
- 详情页和每日复习页显示题目图片；
- 错题列表不加载缩略图，避免分页请求产生大量图片流量；
- 上传新图片会替换旧图片；
- 可以单独移除图片而不删除错题；
- 删除错题后清理对应图片文件；
- 不保存用户提供的原始文件名作为磁盘文件名；
- F-008 不包含 OCR、Dashboard、多图片、对象存储和图片编辑。

- 没有图片替换和单独删除 API；
- 没有文件系统存储服务和配置；

现有字段足以支持单图，F-008 不新增表，也不修改 V1/V2 Flyway 历史。

## 6. 存储设计

### 6.1 配置

新增可覆盖的配置项：

```yaml
app:
  storage:
    question-image-directory: ${APP_QUESTION_IMAGE_DIRECTORY:./data/question-images}

spring:
  servlet:
    multipart:
      max-file-size: 20MB
      max-request-size: 21MB
```

默认目录仅用于本地开发。部署时必须通过 `APP_QUESTION_IMAGE_DIRECTORY`
指向持久化卷或明确的外部数据目录。`backend/data/` 必须加入 Git 忽略规则，
图片文件不得进入版本控制。

### 6.2 相对路径

数据库只保存由服务端生成的相对路径：

```text
questions/{questionId}/{uuid}.{extension}
```

规则：

- `questionId` 来自数据库；
- 文件名由 UUID 生成；
- 扩展名由服务端识别的实际格式决定；
- 不使用客户端文件名拼接磁盘路径；
- 每次解析路径后必须确认规范化绝对路径仍位于配置根目录之下；
- API 不接受任意路径参数。

### 6.3 格式识别

不能只相信扩展名或 `Content-Type`。服务端至少检查文件头：

| 格式 | 接受的内容类型 | 文件头要求 |
| --- | --- | --- |
| PNG | `image/png` | PNG 固定签名 |
| JPEG | `image/jpeg` | JPEG SOI 签名 |
| WebP | `image/webp` | RIFF + WEBP 签名 |
| GIF | `image/gif` | GIF87a 或 GIF89a |

客户端类型、服务端识别结果和扩展名不一致时，以服务端识别结果为准；无法
识别时拒绝上传。SVG 即使声明为 `image/*` 也必须拒绝。

### 6.4 文件大小

- 业务常量为 `20 * 1024 * 1024` 字节；
- 空文件拒绝；
- 超限请求返回 413；
- 前端先做同样的大小与格式检查以便及时反馈；
- 服务端校验仍是最终边界。

## 7. API 设计

### 7.1 上传或替换

```text
PUT /api/questions/{questionId}/image
Content-Type: multipart/form-data
字段名: file
```

成功返回 200：

```json
{
  "questionId": 123,
  "imagePath": "questions/123/generated-name.png",
  "contentType": "image/png",
  "size": 102400
}
```

同一接口同时承担首次上传和替换。客户端不能提交 `imagePath`。

### 7.2 读取

```text
GET /api/questions/{questionId}/image
```

- 返回原始图片字节和正确 `Content-Type`；
- 使用 `Content-Disposition: inline`；
- 设置 `X-Content-Type-Options: nosniff`；
- 第一版使用禁止缓存或明确重新验证策略，避免替换后继续显示旧图片；
- 错题不存在或没有图片时返回 404 JSON 错误，不泄露磁盘路径。

### 7.3 移除

```text
DELETE /api/questions/{questionId}/image
```

- 成功返回 200 和统一消息 JSON；
- 数据库 `image_path` 置为 `NULL`；
- 事务提交后删除旧文件；
- 没有图片时返回 409，防止把无变化操作伪装为成功。

### 7.4 既有响应

- `QuestionDetailResponse.imagePath` 继续表示图片是否存在及当前存储键；
- `DueQuestionResponse.imagePath` 已存在，无需扩展到期队列契约；
- 每日复习可以在查看答案前显示题图，同时仍然只在用户点击“查看答案”后
  调用错题详情接口；
- 错题分页摘要继续不返回图片字节，也不增加缩略图请求。

## 8. 后端结构

建议新增：

```text
question/image/
├── config/QuestionImageStorageProperties.java
├── controller/QuestionImageController.java
├── dto/QuestionImageResponse.java
├── exception/QuestionImageNotFoundException.java
├── exception/QuestionImageStorageException.java
├── model/StoredQuestionImage.java
└── service/
    ├── QuestionImageService.java
    └── LocalQuestionImageStorage.java
```

职责：

- Controller 只处理 multipart、HTTP 状态和响应头；
- `QuestionImageService` 处理错题存在性、数据库路径更新和事务协调；
- `LocalQuestionImageStorage` 只处理受控根目录内的文件校验、写入、读取和删除；
- `QuestionService.delete` 在删除错题时登记提交后的文件清理；
- `GlobalExceptionHandler` 统一返回图片校验、超限、缺失和存储失败错误。

不把文件 I/O 直接堆进 `QuestionController` 或 `QuestionService`。

## 9. 数据库与文件系统一致性

文件系统不参与 MySQL 事务，必须显式处理部分成功：

### 上传/替换

1. 校验错题和文件；
2. 先写临时文件；
3. 在同一文件系统中原子移动到生成后的最终路径；
4. 更新 `question.image_path`；
5. 数据库回滚时删除新文件；
6. 数据库提交后删除旧文件；
7. 旧文件删除失败时记录错误，不能把数据库重新指回旧文件。

### 单独移除

1. 将数据库路径置空；
2. 数据库提交后删除旧文件；
3. 删除失败时记录孤儿文件，不能让 API 返回一个仍指向已移除图片的状态。

### 删除错题

1. 在删除数据库记录前保存旧相对路径；
2. 沿用现有数据库事务删除错题及其关联复习数据；
3. 提交后删除图片文件和空题目目录；
4. 没有图片的旧题保持原有删除行为。

F-008 不承诺跨 MySQL 与文件系统的绝对原子性，但必须保证数据库不会持久化
指向上传失败文件的路径，并尽量避免产生孤儿文件。

## 10. 前端交互

### 10.1 共享图片控件

在 `QuestionForm` 中集成或组合独立的 `QuestionImageField`：

- 选择一张本地图片；
- 显示文件名、大小和本地预览；
- 选择前检查格式和 20 MiB 上限；
- 可以清除尚未上传的选择；
- 编辑时显示现有图片；
- 编辑时可以选择替换或确认移除；
- 提交期间禁用重复操作；
- 组件卸载或替换预览时释放 `URL.createObjectURL`。

### 10.2 创建错题

创建仍先提交现有 JSON，获得 `questionId` 后再上传图片：

```text
POST /api/questions
→ 成功获得 ID
→ 如果选择了图片则 PUT /api/questions/{id}/image
```

如果 JSON 创建成功但图片上传失败：

- 不自动重发创建请求，避免产生重复错题；
- 明确提示“错题已保存，但图片上传失败”；
- 跳转到该错题编辑页，允许只重试图片；
- 不能向用户显示“整道错题保存失败”。

### 10.3 修改错题

- 文字/知识点更新和图片操作是两个明确请求；
- 只修改文字时不触碰原图片；
- 新图片上传成功后替换旧图片；
- 移除图片使用独立 DELETE；
- 部分成功时准确说明已经保存的部分，不能自动重发非幂等请求。

### 10.4 详情与每日复习

- `imagePath !== null` 时请求 `/api/questions/{id}/image`；
- 图片按容器宽度缩放，保持原始比例；
- 点击图片可查看大图；
- 加载失败显示局部错误和“重新加载图片”，不遮蔽文字内容；
- 每日复习题图属于题目本身，在查看答案前显示；
- 答案和解析继续保持 F-007 的按需加载规则。

## 11. 错误响应

至少覆盖：

| 场景 | HTTP | 要求 |
| --- | ---: | --- |
| 错题不存在 | 404 | 沿用错题不存在语义 |
| 错题没有图片 | 404 | 图片资源不存在，不把整道题视为不存在 |
| 文件为空 | 400 | 指出图片不能为空 |
| 格式不支持或签名无效 | 400 | 指出允许格式 |
| 文件超过 20 MiB | 413 | 明确大小上限 |
| 重复移除空图片 | 409 | 状态无变化 |
| 存储目录不可写 | 500 | 通用存储失败信息，不泄露本机路径 |

图片读取失败不能破坏题目详情和每日复习页面的文字部分。

## 12. 安全与工程约束

- 不信任原文件名、扩展名或客户端 MIME；
- 拒绝 SVG，避免把可执行脚本内容作为图片同源返回；
- 防止 `..`、绝对路径、符号链接和根目录逃逸；
- 返回头使用 `nosniff`；
- 错误响应和日志不返回完整本机路径；
- 上传目录不放在前端公开目录；
- 不允许用户通过 API 枚举任意磁盘文件；
- 不把上传文件提交到 Git；
- 不为了单机单用户场景引入对象存储 SDK、消息队列或异步任务系统。
