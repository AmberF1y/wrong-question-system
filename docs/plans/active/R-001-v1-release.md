## 5. 本地长期使用约定

### 5.1 固定路径

默认约定：

```text
仓库：D:\Projects\wrong-question-system
图片：D:\WrongQuestionData\question-images
备份：D:\WrongQuestionBackups
数据库：wrong_question_system
时区：Asia/Shanghai
```

脚本允许通过参数覆盖这些路径，但不得把数据库密码写入仓库、配置文件、日志
或命令历史。启动脚本只读取当前 PowerShell 进程中的 `DB_PASSWORD`。

### 5.2 启动方式

新增 `scripts/start-local.ps1`：

- 必须在 Windows PowerShell 5.1 下可解析；
- 从脚本位置自动确定仓库根目录，不硬编码用户名；
- 校验 Java、Node、npm、MySQL 配置、仓库路径和图片目录；
- 要求调用者预先设置 `DB_PASSWORD`；
- 设置 `APP_REVIEW_ZONE_ID` 和 `APP_QUESTION_IMAGE_DIRECTORY`；
- 分别启动后端与前端窗口；
- 等待后端健康检查和前端地址可访问；
- 端口已占用或启动失败时给出明确错误；
- 不自动执行数据库 baseline，也不修改 Git 工作区。

### 5.3 停止方式

第一版不实现后台服务管理器。用户通过启动脚本打开的两个 PowerShell 窗口
使用 `Ctrl+C` 停止服务。备份前必须停止后端，避免 MySQL 与图片目录跨存储
复制时出现不一致。

## 6. 备份与恢复

新增 `scripts/backup-local.ps1`：

- 默认备份正式库 `wrong_question_system` 和固定图片目录；
- 后端端口仍在监听时拒绝备份；
- 使用 `mysqldump --single-transaction` 导出数据库；
- 使用交互式密码提示，不把密码拼进命令参数；
- 复制图片目录并保留相对结构；
- 生成包含文件大小和 SHA-256 的清单；
- 生成备份汇总，记录时间、数据库、图片目录和 Git 提交；
- 失败时不把不完整目录伪装为成功备份。

`docs/local-usage.md` 必须写明恢复流程。恢复数据库或覆盖正式图片属于破坏性
操作，不由脚本自动执行；真正需要恢复时先检查备份清单，再执行人工确认的
独立恢复步骤。

## 7. 验证范围

### 7.1 静态验证

- 两个 PowerShell 脚本在 Windows PowerShell 5.1 下解析通过；
- 脚本不包含真实密码、用户专属临时目录或验收数据；
- `git diff --check` 通过；
- 变更路径只落在本计划允许的版本元数据、文档和 `scripts/` 中。

### 7.2 全量发布回归

- 后端 `mvnw.cmd clean test` 全量通过；
- 前端 `npm.cmd run test:unit -- --run` 全量通过；
- 前端 `npm.cmd run type-check` 通过；
- 前端 `npm.cmd run build` 通过；
- 回归结束工作区 clean；
- 日志与汇总保存在仓库外并记录 SHA-256。

### 7.3 启动冒烟验证

- 使用固定图片目录启动后端；
- 启动前端并确认后端连接状态；
- `/api/health` 返回 200；
- 关闭并重新启动后仍能读取正式库和既有图片；
- 启动脚本没有修改 Git 工作区。

### 7.4 真实使用起点

在正式开发库创建至少一道用户实际需要保留的错题，不作为临时验收数据删除：

- 使用真实科目和知识点；
- 填写完整题目、错误答案、正确答案、解析和错误原因；
- 可选上传一张真实题目图片；
- 确认详情页和每日复习流程可用；
- 确认首次复习日期为创建业务日期加一天。

真实学习数据不进入 Git，也不复制到发布证据目录。

### 7.5 备份验证

- 停止后端后执行一次正式备份；
- SQL 文件非空；
- 图片数量与正式图片目录一致；
- 清单中的 SHA-256 可以重新核验；
- 备份目录不位于 Git 仓库内；
- 不执行会覆盖正式数据的恢复演练。
