## 4. Feature 目标

F-006 的目标是把 F-003、F-004 和 F-005 已完成的后端数据能力转化为可以直接使用的桌面浏览器界面，打通：

```text
打开前端
→ 查看知识树
→ 维护知识点
→ 录入错题
→ 浏览和筛选错题
→ 查看错题详情
→ 修改或删除错题
```

完成后，用户无需 PowerShell、Postman 或直接操作数据库，即可完成知识点和错题的日常维护。

F-006 只展示复习状态摘要，不实现“获取今日待复习题 → 查看答案 → 评价 → 下一题”的复习交互。该闭环留给 F-007。

## 6. 技术方案

### 6.1 核心技术

采用 ADR-001 已确认的前端技术栈：

- Vue 3；
- TypeScript；
- Vite；
- Element Plus。

补充以下直接服务本 Feature 的依赖：

- Vue Router：管理多页面路由；
- Pinia：共享知识树状态；
- Axios：封装 REST API 请求；
- `@element-plus/icons-vue`：使用 Element Plus 图标；
- Vitest：前端测试运行器；
- Vue Test Utils：Vue 组件测试；
- jsdom：提供组件测试所需的浏览器 DOM 环境。

不引入第二套 UI 框架、Tailwind CSS、VueUse、TanStack Query、Mock Service Worker 或表单框架。

### 6.2 Vue 编写方式

统一使用：

- 单文件组件 `.vue`；
- Composition API；
- `<script setup lang="ts">`；
- 明确的 TypeScript 类型；
- 组件 `props` 与 `emits`；
- 业务状态和请求状态分离。

不混用 Options API。

### 6.3 Element Plus 引入方式

F-006 采用全量注册 Element Plus，并显式引入其样式。

原因：

- 当前为个人桌面应用，首要目标是稳定和可理解；
- 不需要为了当前体量增加自动导入插件和额外 Vite 配置；
- 后续若构建体积成为真实问题，再切换按需加载。

### 6.4 Pinia 使用边界

Pinia 只用于确有跨页面复用价值的知识树数据：

- 完整知识树；
- 知识树加载状态；
- 刷新知识树；
- 根知识点列表；
- ID 到节点和根节点的派生信息。

错题表单、分页条件和详情请求保持为页面局部状态，不把所有数据都塞入全局 Store。

## 9. 应用布局和视觉原则

第一版以前台工作界面为主，不制作营销首页。

桌面端布局包括：

- 左侧导航：错题管理、知识点管理；
- 顶部区域：当前页面标题和后端连接状态；
- 主内容区：列表、详情或表单；
- 页面级主要操作放在标题区域右侧。

视觉采用低干扰的蓝灰色工作台风格：

- 信息密度适中；
- 正文默认不小于 16px，常用标签不小于 14px；
- 使用统一间距、边框、状态颜色和圆角；
- 危险操作只使用红色；
- 不使用装饰图片、营销文案、大型 Hero 或无功能动画；
- 1280px 及以上桌面视口为主要验收尺寸；
- 窄屏时导航和主要内容不得出现非预期横向滚动，但不进行完整移动端重构。

## 11. 知识点管理页面

### 11.1 页面内容

页面必须展示：

- 完整知识树；
- 新建根知识点按钮；
- 选中节点后的新建子节点、修改和删除操作；
- 加载、空树和请求失败状态。

### 11.2 创建知识点

支持：

- 创建根节点，提交 `parentId: null`；
- 在选中节点下创建子节点，提交该节点 ID；
- 提交成功后关闭对话框、刷新知识树并提示成功；
- 失败时保留已填写内容并显示后端错误。

前端校验：

- 去除首尾空白后不能为空；
- 根节点最多 50 个字符；
- 普通节点最多 100 个字符。

后端仍是重名和其他业务约束的最终判定者。

### 11.3 修改知识点

修改对话框提交完整状态：

```json
{
  "name": "修改后的名称",
  "parentId": 2
}
```

规则：

- 根节点只能改名，父节点固定为 `null`；
- 普通节点可以改名并在同一根知识树内移动；
- 父节点候选不得包含节点自身及其全部后代；
- 不展示其他根知识树中的节点作为候选；
- 后端继续验证循环、自引用、跨树移动和根身份变化。

### 11.4 删除知识点

删除前必须显示确认对话框，并明确说明：

- 有子节点时不能删除；
- 被错题引用时不能删除；
- 删除不会递归处理子树或错题。

成功后刷新知识树。后端返回 409 时显示具体错误，不把失败伪装成成功。

## 12. 知识点选择器

错题表单复用一个多选知识树组件。

必须满足：

- 可选择根节点或普通节点；
- 可同时选择父节点和子节点；
- 只提交直接选择的节点 ID；
- 至少选择一个知识点；
- 不允许重复 ID；
- 所选节点必须属于同一根节点；
- 编辑时能够正确回显现有关联；
- 列表顺序不影响业务含义。

前端发现跨科目选择时阻止提交并显示明确提示；后端仍保留相同业务校验。

## 13. 错题表单

创建和修改共用 `QuestionForm`，字段为：

| 字段 | 展示名称 | 最大长度 |
| --- | --- | ---: |
| `questionText` | 题目 | 10000 |
| `wrongAnswer` | 我的错误答案 | 5000 |
| `correctAnswer` | 正确答案 | 5000 |
| `analysis` | 解析 | 10000 |
| `errorReason` | 错误原因 | 2000 |
| `knowledgePointIds` | 知识点 | 至少 1 个 |

规则：

- 五个文本字段均必填；
- 使用多行输入并保留正文换行；
- 显示当前字符数和最大长度；
- 没有作答时由用户输入“未作答”，不自动把空字符串改成该文字；
- 科目不作为可编辑字段，依据知识点由后端计算；
- `imagePath` 不可编辑且本阶段不显示上传入口；
- 请求中禁用重复提交；
- 创建成功跳转到新错题详情；
- 修改成功返回对应详情；
- 请求失败时保留表单内容。

客户端校验用于尽早反馈；后端 Validation 和业务校验仍是最终约束。

## 14. 错题列表

```http

```

展示：

- 题目摘要；
- 科目；
- 直接关联知识点；

- 下一次复习日期；

## 16. 错题修改和删除

### 16.1 修改

进入编辑页后先加载完整详情，并回显所有可编辑字段。PUT 提交全部字段和知识点集合，不发送只读字段。

修改成功后：

- 跳转到相同 ID 的详情；
- 展示最新数据；
- 复习状态由后端保持，不由前端重建。

### 16.2 删除

列表和详情均允许删除，但必须先确认。

成功后：

- 列表页重新查询当前页；
- 详情页跳转到列表；
- 不主动删除任何知识点。

失败时保留当前页面并显示错误。

## 17. 复习状态展示

前端映射：

| 后端值 | 中文 |
| --- | --- |
| `ACTIVE` | 复习中 |
| `MASTERED` | 已掌握 |

- 不根据当前日期自行改变后端状态。

## 19. HTTP 与错误处理

### 19.1 Axios 实例

建立单一 Axios 实例：

- `baseURL` 为 `/api`；
- JSON 请求使用标准 `Content-Type`；
- API 模块返回已解析的响应数据；
- 组件不直接拼接后端基础地址。

### 19.2 错误结构

优先解析后端：

```json
{
  "timestamp": "...",
  "status": 409,
  "code": "...",
  "message": "...",
  "path": "...",
  "fieldErrors": {}
}
```

处理规则：

- 有后端 `message` 时展示该信息；
- Validation 的 `fieldErrors` 映射到对应表单字段或汇总提示；
- 无响应时提示无法连接后端；
- 非约定响应使用统一兜底提示；
- 404 详情页显示资源不存在并提供返回入口；
- 409 业务冲突不重试、不覆盖数据；
- 不向用户直接展示 Axios 内部堆栈或原始异常对象。

## 20. 请求状态和并发交互

每个远程操作必须区分：

- 初始状态；
- 加载中；
- 成功；
- 空数据；
- 失败。

写操作期间：

- 禁用对应提交或确认按钮；
- 防止同一操作重复发送；
- 不冻结与该请求无关的整个应用；
- 成功后以服务器响应或重新查询结果为准；
- 失败时不提前修改为成功状态。

前端不实现额外离线缓存、自动重试队列或乐观更新。

## 25. 安全与数据边界

仍需保证：

- 不把数据库密码写入前端、环境文件或 Git；
