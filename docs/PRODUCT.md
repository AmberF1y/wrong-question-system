# Wrong Question & Rolling Review System

## 1. Product Vision

本项目是一个面向个人长期学习使用的 **错题整理 + 滚动复习系统**。

它不只是保存错题的电子笔记本，而是希望解决两个连续的问题：

1. 如何尽可能低成本地将学习过程中产生的错题沉淀下来。
2. 如何在之后合适的时间重新复习这些题目，直到真正掌握。

产品核心价值是：

> 让用户每天打开系统时，都能明确知道今天最值得复习哪些题目，并通过持续滚动复习逐渐消化自己的薄弱知识。

项目首先服务真实个人学习需求，同时允许随着实际使用规模和需求增长逐步演化为具有较完整工程能力的系统。

---

## 2. Target User

第一阶段仅服务单个用户。

当前主要使用场景为考研学习，包括但不限于：

* 数学
* 408 计算机专业基础
* 英语
* 政治

系统设计不应与具体考试强绑定，未来应允许扩展到其他课程和知识体系。

---

## 3. Primary Usage Environment

第一版本以桌面电脑浏览器使用为主。

典型场景包括：

* 学习过程中截取题目图片。
* 将错题图片上传到系统。
* 编辑和整理错题信息。
* 每天在电脑上完成错题复习任务。

移动端支持不是第一阶段核心目标。

---

## 4. Core Problems

### 4.1 错题录入成本高

传统错题整理通常要求用户手工复制题目、答案和解析，整理成本较高，容易导致系统长期无法坚持使用。

理想状态下，系统允许：

```text
上传题目图片
↓
自动识别题目文字
↓
生成可编辑文本
↓
用户进行少量修正和补充
↓
保存错题
```

OCR / 图片文字提取是产品期望能力。

如果 MVP 阶段暂时无法以合适成本实现可靠 OCR，可以退化为：

```text
图片 + 手工补充文字
```

F-008 已落地这一退化方案：每道错题可以保存一张可选原始图片，同时继续
手工填写题目、答案、解析和错误原因。OCR 仍是后续增强，不属于当前能力。
系统设计应避免阻碍后续加入 OCR，但不为 OCR 提前引入任务表或异步流程。

---

### 4.2 错题保存后容易被遗忘

仅仅建立错题库不能真正解决学习问题。

系统需要主动维护每道题的复习状态，并根据用户的掌握程度安排未来复习时间。

---

### 4.3 不清楚自己的薄弱知识点

随着错题数量增加，用户需要从知识维度理解自己的薄弱区域，而不仅仅看到孤立错题。

因此错题需要与结构化知识体系关联。

---

## 5. Core User Workflow

### 5.1 错题录入

```text
发现错题
↓
上传题目图片
↓
OCR 提取文字（目标能力）
↓
用户修正题目文字
↓
填写错题相关信息
↓
关联科目和知识点
↓
保存
↓
进入待复习系统
```

---

### 5.2 每日复习

```text
打开系统
↓
查看今日待复习数量
↓
开始今日复习
↓
只显示题目
↓
用户在线下 / 纸上重新作答
↓
点击“查看答案”
↓
显示正确答案和解析
↓
用户评价掌握程度
↓
系统计算下一次复习日期
↓
进入下一题
```

复习过程中不要求用户将本次答案重新输入系统，以减少操作成本。

---

### 5.3 已掌握题抽查

当一道题达到系统规定的“已掌握”状态后：

```text
退出正常滚动复习队列
↓
进入已掌握题集合
↓
日常复习时偶尔抽取
↓
确认是否仍然掌握
```

具体抽查频率和重新进入普通复习队列的规则，由后续 Feature 单独设计。

---

## 6. Wrong Question Information

一道错题至少需要包含以下核心信息：

* 题目
* 我的错误答案
* 正确答案
* 解析
* 错误原因
* 所属科目
* 一个或多个知识点

题目同时可以保存最多一张可选原始图片。当前支持 PNG、JPEG、WebP 和 GIF，
单文件最大 20 MiB；图片用于保留公式、图表和原题排版，不替代必填文字。

未来可以根据需求增加：

* 来源
* 创建时间
* 最近修改时间
* 难度
* 备注
* OCR 原始结果
* 其他学习元数据

这些暂时不作为核心产品要求。

---

## 7. Knowledge System

系统采用预先建立的结构化知识体系，而不是仅使用完全自由的标签。

例如：

```text
408
└── 计算机网络
    └── 传输层
        └── TCP
            └── 拥塞控制
```

知识体系必须满足：

* 可以新增知识节点。
* 可以修改已有节点。
* 可以调整知识层级。
* 可以随着学习过程不断扩充。
* 一道错题可以关联多个知识点。

知识体系不应在第一版被硬编码到程序逻辑中。

---

## 8. Review Model

第一阶段采用简单、明确、容易验证的固定滚动复习规则。

不在 MVP 阶段实现复杂的记忆模型。

示意：

```text
不会
→ 较短时间后再次复习

模糊
→ 短期再次复习

基本掌握
→ 延长复习间隔

熟练
→ 更长时间后再次复习
```

F-005 已确认第一版间隔：不会 1 天、模糊 3 天、基本掌握 7 天、
熟练 14 天；连续两次熟练后进入 `MASTERED`。

新录入错题默认在：

> 第二天进入第一次正式复习。

---

## 9. Mastery Evaluation

复习后由用户进行自我评价。

第一版不使用传统“正确率”作为主要指标。

产品更关注：

> 掌握程度 / 掌握率

F-005 已确认评价等级为：

* 不会
* 模糊
* 基本掌握
* 熟练

系统根据评价结果调整下一次复习计划。

---

## 10. 后续 Home Dashboard

Dashboard 是完成核心闭环后的后续增强，不属于 `v1.0.0`。当前第一版直接以
“每日复习”作为学习入口，已经可以获取并完成到期题目。

未来首页可重点展示能够直接帮助当天学习决策的信息。

至少包括：

### 今日复习

* 今日待复习题目总数
* 各科目待复习数量
* 开始今日复习入口

### 学习反馈

* 当前薄弱知识点
* 掌握率趋势

暂时不追求复杂的数据可视化。

## 11. MVP Scope

第一版必须打通完整使用闭环。

### 错题录入

* 创建错题
* 保存题目图片
* 保存和编辑题目文字
* 填写错误答案
* 填写正确答案
* 填写解析
* 填写错误原因
* 选择科目
* 关联一个或多个知识点

### 知识体系

* 查看知识树
* 新增知识点
* 修改知识点
* 调整或扩充知识体系
* 一题关联多个知识点

### 错题管理

* 查看已有错题
* 修改错题
* 浏览错题库

### 滚动复习

* 根据固定规则生成复习日期
* 新题默认第二天首次复习
* 生成今日复习队列
* 复习时默认隐藏答案
* 主动查看答案和解析
* 用户评价掌握程度
* 更新下一次复习日期
* 支持进入“已掌握”状态

### 已掌握题

* 已掌握题退出普通滚动队列
* 保留已掌握题记录
* 为后续随机抽查机制提供基础

### 用户

* 第一版仅支持单用户

`v1.0.0` 的闭环边界到此为止。Dashboard、各科目统计卡片、薄弱知识点聚合和
掌握率趋势均不属于本节的第一版必需项。

> 时间维度滚动复习 + 知识维度专项强化

* 高级筛选

## 14. Product Principles

### 真实使用优先

系统首先必须真正解决用户每天学习中的问题。

### 低操作成本

任何新增字段或操作，都需要考虑：

> 它带来的价值是否值得用户每一道题都多执行一次操作。

### 完整闭环优先

第一版必须实现：

```text
录入
→ 保存
→ 调度
→ 复习
→ 评价
→ 再调度
```

而不是停留在普通错题 CRUD 系统。

### 简单方案优先

在简单实现能够满足真实需求时，不主动引入复杂基础设施。

### 为演进保留空间，而不是提前实现未来

允许设计具备合理扩展空间，但不为尚不存在的需求提前建设复杂系统。

---

## 15. Product Success Criteria

MVP 是否成功，不以代码量或技术栈复杂度判断。

第一阶段至少应该满足：

1. 用户可以持续录入真实学习过程中产生的错题。
2. 录入成本低到足以长期坚持。
3. 系统可以每天自动形成明确的复习任务。
4. 用户能够完成“题目 → 回忆 → 查看答案 → 自评”的完整过程。
5. 系统能够根据评价安排后续复习。
6. 用户可以按科目和知识点组织、查看并筛选错题。
7. 结构化知识点、复习状态和历史数据能够为未来薄弱区域分析、算法升级、
   专项训练和统计分析提供基础。

---

## 16. F-005 Fixed-Rule Rolling Review

F-005 将产品从错题 CRUD 推进到首个可用的滚动复习闭环，采用明确、可解释的固定规则：

| 用户评价 | 下一次复习 |
| --- | ---: |
| 不会 | 实际完成日 + 1 天 |
| 模糊 | 实际完成日 + 3 天 |
| 基本掌握 | 实际完成日 + 7 天 |
| 熟练 | 实际完成日 + 14 天 |

连续两次评价为“熟练”后，错题进入 `MASTERED`，退出常规待复习队列。任意其他评价都会把连续熟练次数重置为 0。

当前队列包含所有到期和逾期错题，固定按“最早到期优先、同日题目 ID 升序”排列，每次动态返回一题。用户查看答案时复用错题详情接口，评价成功后再获取下一题。

新错题首次复习日期为创建业务日期加 1 天。已有错题由数据库迁移按原 `created_time` 日期加 1 天初始化，不伪造历史。

已掌握错题可以手动重新加入，重新加入后当天到期、连续熟练次数归零，保留最后一次真实评价时间，并记录 `REACTIVATION` 历史。

F-005 保存历史但不提供历史查询 API，也不保存当时的题目内容快照。

### 16.1 F-005 Explicitly Excluded

本阶段仍不实现：

- 已掌握题随机抽查；
- 自适应间隔、SM-2 或 FSRS；
- 用户级时区配置；
- 复习历史展示；
- Dashboard 与趋势统计；
- 前端复习页面；
- 图片上传与 OCR。

## 17. F-008 Question Image Upload and Management

F-008 将 MVP 的“图片 + 手工文字”录入方式落地为真实可用能力：

```text
创建或修改错题
→ 选择一张可选图片并本地预览
→ 后端校验实际文件内容
→ 本地文件系统保存图片
→ MySQL 保存相对路径
→ 详情与每日复习按需显示
```

当前产品规则：

- 每道错题最多一张图片，没有图片仍可正常创建、修改和复习；
- 支持 PNG、JPEG、WebP、GIF，单文件最大 20 MiB；
- 创建页和编辑页提供文件名、大小与本地预览；
- 上传新图片替换旧图片，也可以单独移除图片；
- 删除错题时清理对应图片；
- 详情页支持按比例显示、大图查看和局部失败重试；
- 每日复习在查看答案前显示题图，答案仍按用户操作延迟加载；
- 错题列表不加载缩略图，避免分页产生额外图片请求。

图片上传和文字保存是两个明确请求。创建错题时先保存 JSON 并取得 ID，再
上传图片；如果图片失败，已经创建的错题不会被重复提交，页面会进入编辑页
允许只重试图片。修改时只改变文字不会触碰原图，图片操作失败也不会自动
重发已经成功的文字请求。

F-008 明确不包含：

- OCR 或 AI 文字识别；
- 多图片、排序、裁剪、旋转、压缩或格式转换；
- 对象存储、CDN 或图片存入 MySQL BLOB；
- Dashboard、统计、搜索或复习算法修改；
- 用户与权限隔离。
